# AGENTS.md — rules for AI coding agents

GameMonsterJS2D (since 4.0.0) is a **project starter**: the npm package `create-gamemonsterjs2d` copies `template/` (Vite + Phaser 4 + Tiled + TypeScript) into a new folder and runs `npm install`.

- `bin/create.mjs` — the CLI, Node ≥ 20.19, no dependencies. The template keeps `.gitignore` as `template/_gitignore` (npm never publishes `.gitignore`); the CLI renames it.
- `template/` — a working game. Work on it in place: `cd template && npm install && npm run dev`. `template/AGENTS.md` is the guide for agents in the user's project — keep it in sync.
- Stack decisions: Matter.js is used through Phaser (`physics.default = "matter"`), never as a separate package; sound goes through Phaser's sound manager, no Howler.
- Template dev dependencies beyond the toolchain: Tweakpane (dev tools, `src/debug/`, loaded only behind `import.meta.env.DEV` so it never reaches `dist/`), `maxrects-packer` + `pngjs` for `scripts/atlas.mjs` (pure JS, no native builds), `zod` (content schemas, used only by `content/validate.ts` in the Vite plugin and tests), `@types/node`. Runtime dependency stays Phaser only — check `npm run size` after changes. Capacitor, Electron, electron-builder, steamworks.js and @sentry/cli are installed on demand by the scripts (`mobile:init`, `desktop:init`, `sentry:sourcemaps`), never in the template's package.json.
- Level: `template/public/assets/maps/level1.tmj` (Tiled JSON, embedded tileset `tiles`, 18 px tiles), listed in `template/content/levels.json`. Keep layer names `decor`, `ground`, `objects` and object names `player`, `coin`, `slime`, `flag` in sync with `GameScene.ts` and `content/validate.ts` (`LAYERS`, `REQUIRED_OBJECTS`). Balance and texts live in `template/content/` too; a genre template that needs other required objects must keep them compatible with the validator.
- Optional services in the template are off until configured: the game server `template/server/` (no dependencies; its tests run in `npm run check`), Sentry/Metrica sinks (`.env`), Android (`capacitor.config.json`, `scripts/mobile.mjs`), desktop (`desktop/`). Genre templates must emit the same `gameEvents` (`levelStart`, `death`, `checkpoint`, `levelEnd`), call `startLives()`, `applyGameSpeed()`, `applyColorMode()`, `addLevelLight()`, `rng.seed()` and `loadLevel()` like the platformer GameScene.
- Assets: only CC0 or own work; list every file in `template/public/assets/CREDITS.md`.
- Player texts Russian, code comments English.
- Before a release: `npm pack`, `npx ./create-gamemonsterjs2d-<v>.tgz "Test Game"` in a temp folder, `npm run build` there, play it in `npm run dev` (keyboard and touch), no console errors.
- Versions: `version` in package.json + CHANGELOG.md + tag `vX.Y.Z`; published tags are never changed.
- `index.html` in the root is the GitHub Pages page: only a short install guide, Inter font, light/dark theme.
- Tags v1.0.0–v3.0.0 hold the former CDN library (ArcadeJS / GameMonsterJS). Lesson repos pin them through jsDelivr — never delete those tags.
- `PROMT.md` (Russian fill-in brief for AI assistants) lives in the root for download and as `template/PROMT.md` in every new project — keep both copies identical and in sync with the template (stack, scripts, file names).
- Genre templates: `templates/<name>/` = `template.json` (title, description, `append` list) + `files/` (copied over the platformer template before any SDK: `src/genre.ts`, `src/scenes/GameScene.ts`, its entities, `public/assets/maps/*`) + `append/` (added to AGENTS.md / README.md). `bin/create.mjs` lists them for `--template=<name>` and the interactive question; `platformer` is the template itself. A genre keeps the shared contracts: `GameScene` exposes `player` (with `x`, `y`, `body`, `respawn`), `level`, `fx`, `look`, `win()`, `pause()`; sets `registry.genre`; `GENRE` describes controls/keys/touch/tuning. Release check: create a project for every genre and run `npm run check` and `npm run test:e2e` there (the first e2e run of a genre saves its golden `*.<genre>.expected.json` — copy the topdown ones back into `template/e2e/golden/` so projects start with them).
- Platform SDKs: the game calls only `platform` from `template/src/platform/` (interface `types.ts`, no-SDK implementation `none.ts`, `index.ts` picks one). Each SDK lives in `sdks/<name>/`: `sdk.json` (title, package scripts/dependencies merged into the project, list of docs to append), `files/` (copied over the template: `src/platform/<name>.ts`, an `index.ts` that exports it, its docs) and `append/` (text added to the end of AGENTS.md, README.md, PROMT.md). `bin/create.mjs` lists `sdks/` automatically for `--sdk=<name>` and the interactive question.
- VK Play is served through `sdks/gamepush` (GamePush detects the portal by the page address; keys in `.env` as `VITE_GAMEPUSH_PROJECT_ID` / `VITE_GAMEPUSH_PUBLIC_TOKEN`, template `.env.example`). VK Play has no public HTML5 SDK of its own — do not invent one.
- Adding an SDK (CrazyGames, Poki…): new `sdks/<name>/` with the same layout; implement every `Platform` method (fall back to `none.ts` when the SDK script is missing so `npm run dev` keeps working); a new method goes to `types.ts` + `none.ts` + every SDK. Both GameMonsterJS2D and GameMonsterJS3D share the same `src/platform/*` and `sdks/yandex/files/src/platform/*` files — keep them identical.
- Release check for SDKs: create a project for every `--sdk` value and build it; test `yandex` with the real dev SDK (`npm run yandex`, or serve `dist/` with the proxied `/sdk.js` next to it): LoadingAPI.ready, GameplayAPI start/stop, fullscreen ad open/close with pause/resume, setData, setScore.
