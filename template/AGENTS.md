# AGENTS.md — rules for AI coding agents

2D browser game on **Vite + Phaser 4 + TypeScript**, levels made in **Tiled**. Created with `npm create gamemonsterjs2d`.

## Phaser docs for agents

Phaser ships its own skills: `node_modules/phaser/skills/<topic>/SKILL.md` (scenes, sprites-and-images, animations, physics-arcade, physics-matter, tilemaps, input-keyboard-mouse-touch, audio-and-sound, cameras, tweens, particles, v3-to-v4-migration…). Read the relevant one before writing Phaser code. This is **Phaser 4**: no `setTintFill` (use `setTint().setTintMode(Phaser.TintModes.FILL)`), FX and masks are filters, `roundPixels` defaults to false. Do not copy Phaser 3 snippets blindly.

`PROMT.md` is the user's game design document; the whole file is the prompt. When the user asks to build from it, follow it: plan and questions first (including every unfilled `«…»` field), then stages; the rules below stay in force.

## Structure

- `content/` — game content as data, edited without code: `balance.json` (WORLD, PLAYER, CAMERA, FX, POINTS), `levels.json` (key, file, title, optional `assets` and `light`), `i18n/<lang>.json` (texts); `schema.ts` (zod schemas — the meaning and range of every field, unknown fields are errors), `validate.ts` (`validateContent()`: schemas + maps (layers, `player`, `flag`, hint keys) + translations (keys, placeholders, plural forms, length)). Checked by the Vite plugin in `vite.config.ts` (error overlay in `npm run dev`, failed `npm run build`) and `src/content.test.ts`. zod is a dev dependency and never reaches `dist/`.
- `src/main.ts` — game config: size 960×540 (`Scale.FIT`), `pixelArt`, physics, gamepad, list of scenes; telemetry sinks from `.env` (`VITE_SENTRY_DSN`, `VITE_METRICA_ID`, `VITE_BACKEND_URL`), `connectSystems()`; platform init + remote config; dev tools in `npm run dev`.
- `src/config.ts` — re-exports `content/balance.json` as `GRAVITY`, `PLAYER`, `CAMERA`, `FX` (mutable copies: dev panel, remote config), speeds, lives, points; text style; **`FEATURES`** — switches of the optional systems (level select, checkpoints, hints, parallax, achievements, daily reward, rotate prompt, remote config URL).
- `src/events.ts` — `gameEvents`: typed events (`levelStart`, `death`, `checkpoint`, `levelEnd`, `sound`); `src/systems.ts` — page-long listeners: analytics (`track`) and the game server (`startRun`/`finishRun`). Scenes emit events, they never call `track()` or the backend for level events.
- `src/random.ts` — `rng` (seeded mulberry32, `createRandom`): GameScene seeds it with the level number; gameplay randomness uses it, never `Math.random()`.
- `src/accessibility.ts` — colour modes (`colorMatrix`, `applyColorMode` on the game camera: contrast, protan, deutan, tritan daltonize), `startLives()` (+2 with help), `canSkipLevel()`, `applyGameSpeed(scene)` (physics/time/tweens), `CAPTIONS` (sound key → i18n key, shown by HudScene).
- `src/backend.ts` — the game server client (`VITE_BACKEND_URL`; off when empty): `backendSink()` (event batches with player id, session, version, A/B variants), `startRun`/`finishRun` (records the run's replay and posts the score), `leaderboard(level)`, `cloudStorage(platform)` (own-site saves also on the server, newer copy wins; portal SDKs unchanged), `transferCode`/`useTransferCode`. `src/player.ts` — anonymous player id + session id. `src/experiments.ts` — A/B: `variant(name, list)`, `runExperiments()` (remote config `experiments`), `assigned`.
- `src/lighting.ts` — `addLevelLight(scene, level.light, player)` (Phaser 4 lights, deferred to the first frame; parallax is tinted, the player stays unlit). `src/bitmapFont.ts` — `makeBitmapFont()` (runtime bitmap font with Cyrillic; HUD score uses "hud"). `src/assets.ts` — `loadLevel()` (map + level assets). `src/plural.ts` — `format()`/`pluralForm()` (Intl.PluralRules). `src/desktop.ts` — `desktopAchievement()` (Steam through the Electron bridge).
- `src/genre.ts` — `GENRE`: platformer (default) or a genre template (`--template=topdown` replaces this file, `GameScene`, the maps and adds its entities). Controls text, key overrides, touch layout, dev-panel tuning object.
- `src/scenes/` — `PreloadScene` (shared assets, animations, generated textures; maps are NOT here) → `MenuScene` (start, quick settings S/M/E, settings O, shop, daily reward) → `LevelSelectScene` (grid with stars, locks) → `GameScene` (one level; `init({ level })`, map loaded in its `preload()`) + `HudScene` (bitmap-font score, lives, touch buttons or joystick, sound captions) + `PauseScene` (resume, volume, effects, restart, skip level with help, menu). `SettingsScene` (volume, effects, language, fullscreen, touch controls, "Accessibility →" page: colours, captions, game speed, help; key re-assignment; progress transfer code with the game server on your own site). `LevelSelectScene` shows the focused level's top 5 with the game server. `ToastScene` — pop-ups above everything, launched once.
- `src/levels.ts` — `LEVELS` (from `content/levels.json`) and progress as plain functions (a level opens when the previous one has an entry: won, or skipped with 0 stars): `starsFor`, `isUnlocked`, `recordResult`, `totalStars`, `parseProgress` (tests in `levels.test.ts`).
- `src/entities/` — `Player` (movement, state machine, juice), `Slime` (patrol, Tiled property `speed`), `MovingPlatform` (Tiled rectangle `platform` with `dx`/`dy`/`speed`, carries the player): one class per entity with `start()`/`step()`.
- `src/movement.ts` — platformer movement as plain math (acceleration, coyote time, jump buffer, variable jump, fall gravity) + `pickPlayerState`; `src/fsm.ts` — `StateMachine`; `src/tiled.ts` — `prop(obj, name, fallback)` for custom properties of Tiled objects.
- `src/input.ts` — `Controls`: actions (`left right up down jump pause confirm`) from keyboard (re-assignable: `keysFor()` = settings → genre → `KEYS`), gamepad and `VirtualButtons` (HUD buttons/joystick; taps shorter than a frame are kept); `justPressed`/`isDown`/`justReleased`/`axisX`/`axisY`. GameScene's Controls are recordable (`src/replay.ts`).
- `src/fx.ts` — `Fx`: dust, sparks, pop text, squash, flash, hitstop, shake (respect the "Effects" setting); `src/look.ts` — camera filters and `glowLayer()`; `src/parallax.ts` — background layers + generated textures (hills, spring); `src/transition.ts` — `goTo()`/`fadeIn()`; `src/ui.ts` — `MenuList` (keyboard/gamepad/pointer, visible focus, options `gap`/`fontSize`/`focus`).
- `src/audio.ts` — `playSfx(scene, key, volume, { variation, limit })` (random pitch, copy limit; finds the key inside an audio sprite when it is not a file of its own; emits `sound` for captions), `playMusic` (one track, crossfade, same track keeps playing), `stopMusic`, `duckMusic` (pause), `updateMusicVolume`. Fades run on the game clock.
- `src/save.ts` — the one save record: `best`, `wallet`, `levels`, `achievements`, `daily`, `settings` (`sound`, `music`, `effects`, `lang`, `touch`, `keys`, `colors`, `captions`, `gameSpeed`, `assist`) with `parseSave` and `save.update()` (merges, optional delay). The store's storage is `cloudStorage(platform)`.
- `src/achievements.ts` (list + `checkAchievements`), `src/daily.ts` (`claimDaily`, streak), `src/remote.ts` (`applyOverrides`, `loadRemoteConfig`), `src/meta.ts` (`toast`, `unlockAchievements`, `claimDailyReward`) — tested in `meta.test.ts`.
- `src/i18n.ts` — texts from `content/i18n/*.json` (ru/en; `Record<keyof typeof ru, string>` makes a missing key a type error), `t()`, `fmt()` (`{n}` and plural `{n:монета|монеты|монет}`), `currentLanguage()` (settings → platform), `starsLabel`; `src/orientation.ts` — "turn your phone" (HTML `#rotate` + CSS media query).
- `src/telemetry.ts` — `track()` events, `captureErrors()` (with stacks), `reportError()`, sinks: `beaconSink`, `sentrySink(dsn)` (Sentry envelope protocol without the SDK, debug ids from `sentry-cli sourcemaps inject`), `metricaSink(id)`; `src/replay.ts` — input recording/playback; `src/cheats.ts` — dev switches; `src/debug/` — dev tools (F1 overlay, F2 Tweakpane tuning + "Copy values for content/balance.json", F3 hitboxes, F4 god mode, F6 win, F7 record, F8 replay, F9 death heat map / Shift+F9 add deaths from a file — `src/debug/heatmap.ts`), only under `npm run dev`.
- `scripts/` — `zip.mjs` (portal archive), `atlas.mjs` (`npm run atlas`), `size.mjs` (`npm run size`, part of `check`), `pwa.mjs` (`npm run build:web`), `audio.mjs` (`npm run audio`: WAV → OGG/M4A with ffmpeg), `audio-sprite.mjs` + `wav.mjs` (`npm run audio:sprite`: `art/sfx/<name>/*.wav` → one WAV + Phaser audio sprite JSON, pure JS), `aseprite.mjs` (`npm run art [-- --watch]`: `art/aseprite/*` → sheets), `i18n.mjs` (`npm run i18n:export|import`: CSV / Google Sheets), `portal-check.mjs` (`npm run portal`: archive rules), `sentry.mjs` (`npm run sentry:sourcemaps`), `mobile.mjs` (`npm run mobile:init|mobile`: Capacitor Android, `MOBILE.md`), `verify.mjs` (`npm run verify -- <replay> [score]`).
- `server/` — the game server, no dependencies (`npm run server`, `server/README.md`): `index.mjs` (`createGameServer()`: `/events`, `/report(.html)`, `/deaths`, `/scores` with checks from `levels.mjs` (max score per map, `MIN_SECONDS`), `/leaderboard`, `/save`), `report.mjs` (funnel, retention, experiments, errors), `Dockerfile`, tests `server.test.mjs`.
- `desktop/` — Electron app (`main.cjs` with the `app://` protocol, `--smoke` check, optional steamworks.js; `preload.cjs` exposes `window.desktop`; `electron-builder.json`), `DESKTOP.md`. `capacitor.config.json` + `MOBILE.md` — Android.
- `.github/workflows/` — `deploy.yml` (GitHub Pages), `pr.yml` (checks + e2e + build artifact on pull requests), `itch.yml` (butler on version tags).
- `public/assets/maps/level*.tmj` — Tiled maps (JSON). Layers: `decor` (no collision), `ground`, `objects` (points/rectangles by **name**: `player`, `coin`, `slime`, `flag`, `checkpoint`, `spring`, `hint` (property `text` = i18n key), `platform` (rectangle)). Tileset `tiles` embedded, image `maps/tiles.png`, 18×18. Tile properties: `collides` (solid), `oneWay` (solid from above only — planks), `hazard` (hurts). The same image is loaded as the sheet `tiles-sheet` (frames 18×18).
- `public/assets/sprites|sounds` — loaded with `this.load.setPath("assets")`.
- Shared state goes through `this.registry` (`score`, `lives`, `level`, `genre`); HUD listens to `changedata`.
- `src/rules.ts` — game rules as plain functions (stomp, record, lives) with tests.
- `e2e/game.spec.ts` — Playwright: menu settings, shop, level select, run, jump (or walk for top-down), pause, level progress, settings, replay; `e2e/visual.spec.ts` — screenshot tests (snapshots saved on the first run per OS, commit them; `--update-snapshots` after an intended change); `e2e/perf.spec.ts` — FPS with a 4× slower CPU (`npm run test:perf`, `MIN_FPS` env); `e2e/portal.spec.ts` — portal moderation rules (no scroll/selection/context menu, no sound before input, silent hidden tab, language); `e2e/golden.spec.ts` — golden runs: `e2e/golden/*.replay.json` played with a fixed 1/60 s step via `game.headlessStep` (Date.now follows the simulated clock — Phaser tweens use it), end state compared with `<name>.<genre>.expected.json` (saved on the first run), plus the `@verify` test behind `npm run verify`. `RECIPES.md` — step-by-step recipes.

## Rules

- Physics: Arcade by default. Matter.js is built into Phaser (`physics: { default: "matter" }`, `this.matter.add…`) — never install the separate `matter-js` package.
- Sound: Phaser's sound manager, played only through `playSfx(scene, key, volume)` / `playMusic()` from `src/audio.ts` so the menu volume settings (S / M) apply. No Howler. Start music only after user input (browsers block autoplay) — the menu waits for a click/key.
- New level: edit or copy the map in Tiled, keep layer and object names, add it to `content/levels.json` (never load maps in `PreloadScene` — `loadLevel()` does it when the level starts).
- Content: numbers, level lists and texts go into `content/*.json`, not into code; a new field gets a zod rule in `content/schema.ts` (and a cross-file check in `content/validate.ts` if it points to another file). Never import zod or `content/validate.ts` from game code.
- New asset: put it into `public/assets/…`, load it in `PreloadScene`, add a line to `public/assets/CREDITS.md`.
- Input: scenes read actions from `Controls` (`src/input.ts`), never keys directly; call `controls.update()` first in `update()`. A new action goes into `Action`, `KEYS`, `PAD_BUTTONS` and, if needed, a HUD touch button. Every action works with keyboard, gamepad and touch. After a pause call `controls.reset()` (GameScene does it on `resume`).
- Entities: a class in `src/entities/` with `start()` (after adding to a physics group — the group resets the body) and `step()`; modes go through `StateMachine` (`src/fsm.ts`), not boolean flags. Movement and other numeric logic stay plain functions with tests.
- Juice: feedback goes through `this.fx` (`src/fx.ts`); screen-wide effects (shake, flash, hitstop) and filters must respect `save.get().settings.effects`. Glowing objects go into `this.look.glowLayer()`, not one filter per sprite. Phaser 4 filters only — see `node_modules/phaser/skills/filters-and-postfx`.
- Scene changes: `goTo(scene, key, data)` + `fadeIn(this)` in the next scene's create() (`src/transition.ts`); overlays (pause, shop) use `scene.launch` + `scene.pause` and `platform.gameplayStop/Start`. Menus are `MenuList` (`src/ui.ts`).
- Balance numbers live in `content/balance.json` (re-exported by `src/config.ts`); when adding one, also add its rule in `content/schema.ts` and an `addBinding` line in `src/debug/index.ts`. Dev-only code goes to `src/debug/` behind `import.meta.env.DEV` (dynamic import) so it never ships.
- Events: a scene announces what happened with `gameEvents.emit()` (`src/events.ts`, new events go into `GameEventMap`); systems listen in `src/systems.ts`. Analytics: `track(name, data)` for things outside levels (menus, purchases); never send personal data — the player is the anonymous id of `src/player.ts`. Sinks come from `.env` in `src/main.ts`.
- Determinism: gameplay randomness through `rng` (`src/random.ts`), never `Math.random()` (cosmetics may). A change that alters golden runs (`npm run test:golden`) is either a bug or an intended balance change — then update the expected files.
- Game server (`server/`, `src/backend.ts`): optional, everything works without `VITE_BACKEND_URL`; portal SDKs keep their own saves and leaderboards. New level objects that give points must be counted in `server/levels.mjs` (max score), or the server rejects honest scores.
- Optional systems are switched in `FEATURES` (`src/config.ts`); code that belongs to one of them checks its flag, so turning it off never breaks the game.
- Levels: add maps to `content/levels.json` (+ title in `content/i18n/*.json`); never load maps in `PreloadScene`. `GameScene` takes `{ level }`; finishing goes to `levels` (or the next level / menu without the level select). Stars and unlocking are rules in `levels.ts` with tests.
- Level objects come from Tiled by name; their numbers are custom properties read with `prop()` (`src/tiled.ts`), with defaults in `config.ts`.
- Sound: effects through `playSfx` (pitch variation on by default — pass `{ variation: 0 }` for UI and jingles), music only through `playMusic`/`stopMusic`; never `this.sound.stopAll()` (it kills the crossfade).
- Meta: achievements are data in `src/achievements.ts` (title in i18n); call `unlockAchievements(game, run)` at the end of a run. Pop-ups only through `toast()`.
- Key re-assignment: scenes create `Controls` after settings may have changed (every scene does it in `create()`), so new keys apply on the next screen.
- Phaser keyboard events may be delivered twice when several keys arrive in one frame: handlers of `keydown` that toggle something must dedupe by event (see `MenuScene`), or use `Controls.justPressed`.
- Asset paths are relative (`base: "./"` in vite.config.ts), so the build runs from any folder and GitHub Pages.
- In dev mode `window.game` is the Phaser.Game and `window.save` the save store: test with `game.scene.getScene("game")`; `e2e/` uses them too.
- Platform: game code never calls a portal SDK directly — only `platform` from `src/platform` (`init`, `ready` after loading, `gameplayStart`/`gameplayStop` around actual play, `showFullscreenAd` only at logical pauses, `showRewardedAd`, `loadData`/`saveData`, `submitScore`, `lang`, `onPause`/`onResume`). This project uses `none.ts` (localStorage, browser language, no ads). Player texts live in `content/i18n/*.json` and follow `platform.lang`. `npm run zip` packs `dist/` into `game.zip` for game portals.
- Texts for players in Russian by default; code comments in English.
- Game rules (scoring, win/lose, records, damage) are plain functions in `src/rules.ts` without engine code, each with a test in `src/rules.test.ts`. New mechanics follow the same split: the rule in `rules.ts`, the engine glue in the scene/component.
- Saves: only through `save` from `src/save.ts` (`save.load()` once, `save.update(patch)` merges and writes; `save.update(patch, 1000)` for frequent changes — portals limit writes). Every new field gets a default and a check in `parseSave()` so old saves keep loading.
- `src/platform/index.ts` wraps the platform in `guard()`: SDK errors are logged, hanging calls end after a time limit (`LIMITS`), a failed rewarded ad returns `false`. Never call the raw `none.ts` / SDK files directly. Check `platform.features` (`ads`, `purchases`, `leaderboard`) before showing buttons that depend on them.
- Purchases: only through `shop` from `src/shop.ts` (`shop.restore()` once at start, `shop.buy(id)`, `shop.has(id)`, `shop.product(id).price`, `shop.available`). Product ids live in `PRODUCTS` and must match the portal console; consumables get a grant function in `createShop(platform, grants)` and are consumed after delivery. Without an SDK purchases are emulated only under `npm run dev`.
- Portal SDKs (`--sdk=yandex|vk|crazygames|poki`) replace `src/platform/index.ts` and add `src/platform/<name>.ts`; script-loaded SDKs use `loadScript()` from `src/platform/script.ts`. A new SDK implements the whole `Platform` interface (falling back to `none.ts`) and gets a mock in `e2e/sdk-mock.ts`.
- Accessibility: every action works from the keyboard, gamepad and by touch; menus keep visible keyboard focus; no full-screen flashes; volume and "Effects" settings stay in the menu and the pause screen. The accessibility settings (colours, captions, game speed, help) do not depend on "Effects"; a new sound effect gets a caption in `CAPTIONS`; a scene that sets `world.timeScale` must restore the previous value (game speed), as `Fx.hitstop` does.
- Release targets: `npm run portal` before uploading to a portal; Android — `MOBILE.md`, PC/Steam — `DESKTOP.md` (Steam achievement API names = ids in `src/achievements.ts`), itch.io — `.github/workflows/itch.yml`.
- Assets: many small images → an atlas (`npm run atlas`); Aseprite animations → `load.aseprite` + `anims.createFromAseprite`. `npm run size` must stay within the budget in `scripts/size.mjs`.
- Recipes for common changes are in `RECIPES.md` — follow them.

## Check before finishing

```bash
npm run check     # ESLint + tsc + content check + Vitest (game, server, scripts) + vite build + size budget — must pass
npm run test:e2e  # Playwright: game flow, levels, settings, replay, accessibility, portal rules, golden runs, screenshots
                  # (first time: npx playwright install chromium)
npm run portal    # before uploading to a portal: build + archive rules + portal browser checks
npm run test:perf # optional: frame rate with a 4× slower CPU
```

Add a unit test for every new rule and a step in `e2e/game.spec.ts` for every new core mechanic. `e2e/sdk-mock.ts` serves fake Yandex, CrazyGames and Poki SDKs (records calls in `window.sdkCalls`), so portal builds are checked too; VK Bridge works only inside VK, so `--sdk=vk` runs in its no-SDK mode there. Format with `npm run format` (Prettier: no semicolons, double quotes, width 120).
