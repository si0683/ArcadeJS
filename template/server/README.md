# Игровой сервер

Свой сервер для игры на своём сайте или на площадках. Зависимостей нет: только Node.js 20.19+ и файлы в папке данных.

- **Аналитика.** Принимает события `track()` и строит отчёт: воронку по уровням (сколько игроков начали и прошли, от чего умирали, где вышли), удержание (сколько игроков вернулись на 1-й и 7-й день), сравнение вариантов A/B-тестов, частые ошибки.
- **Лидерборд с проверкой.** Сервер отклоняет невозможный результат: очков больше, чем монет и врагов на карте, или уровень пройден быстрее `MIN_SECONDS`. Для каждого рекорда хранит запись ввода: её можно посмотреть в игре (F8) или прогнать заново (`npm run verify`).
- **Облачное сохранение.** На своём сайте (без SDK площадки) прогресс хранится и на сервере. Код переноса из настроек переносит его на другое устройство.

На площадках (Яндекс, VK, GamePush…) сохранения и лидерборд остаются площадочными, сервер получает только аналитику.

## Запуск

```bash
cp server/.env.example server/.env   # задайте ADMIN_TOKEN
npm run server                       # http://localhost:8787
```

В `.env` игры укажите `VITE_BACKEND_URL=http://localhost:8787` и перезапустите `npm run dev`.

Отчёт: `http://localhost:8787/report.html?token=<ADMIN_TOKEN>&days=30`.

## Настройки (server/.env)

| | |
|---|---|
| `PORT` | порт, по умолчанию 8787 |
| `ADMIN_TOKEN` | открывает отчёт и точки смертей; без него отчёт выключен |
| `ALLOWED_ORIGINS` | адреса сайтов с игрой через запятую; `*` — любые |
| `DATA_DIR` | папка данных, по умолчанию `server/data` |

## Точки входа

| | |
|---|---|
| `POST /events` | пачка событий `{ player, session, version, exp, events }` (игра шлёт сама) |
| `GET /report`, `/report.html` | отчёт JSON / страница; `?token=…&days=30` |
| `GET /deaths?level=1` | точки смертей для тепловой карты: сохраните ответ в файл и откройте в игре Shift+F9 |
| `POST /scores` | результат уровня `{ player, level, score, seconds, replay }` |
| `GET /leaderboard?level=1&limit=10&player=…` | лучшие результаты, игроки анонимны (`#3f2a9`) |
| `GET /save`, `PUT /save` | облачное сохранение по id игрока и секрету его устройств (`{ data: null }`, пока его нет) |
| `GET /health` | проверка, что сервер жив |

## Данные

- `events/ГГГГ-ММ-ДД.jsonl` — события по дням, одна строка на событие.
- `players.json` — день первого появления каждого игрока (для удержания).
- `scores.json` — лучшие результаты, `replays/<уровень>/<игрок>.json` — записи ввода рекордов.
- `saves/<игрок>.json` — облачные сохранения (секрет хранится как SHA-256).

Персональных данных нет: игрок — случайный id браузера. Бэкап — копия папки.

## Выкладка

На VPS: Node.js 24, `npm run server` под systemd или pm2, перед ним nginx с HTTPS (игры на площадках открываются по https, запросы на http браузер заблокирует).

Docker (собирать из папки проекта: серверу нужны `content/` и карты):

```bash
docker build -f server/Dockerfile -t my-game-server .
docker run -d -p 8787:8787 -v game-data:/app/server/data -e ADMIN_TOKEN=… -e ALLOWED_ORIGINS=https://my-game.example my-game-server
```

После правки уровней пересоберите образ: пределы очков считаются по картам.

## Масштаб

Файлы подходят для игры с тысячами игроков в день. Если отчёт стал медленным, берите меньший `days` или переносите события в ClickHouse или PostgreSQL. Формат строк для этого уже готов.
