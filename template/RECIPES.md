# Рецепты: как развивать игру

Пошаговые инструкции для частых задач. Каждый рецепт заканчивается проверкой: `npm run check` (линтер, типы, тесты, сборка) и `npm run test:e2e` (игра в браузере).

## Новый враг

Пример — летучая мышь, которая летает влево-вправо. Враг — отдельный класс в `src/entities/`, как `Slime.ts`.

1. **Картинка.** Положите `public/assets/sprites/bat.png` (кадры 24×24 в одну строку). Автора и лицензию допишите в `public/assets/CREDITS.md`.
2. **Загрузка и анимация** в `src/scenes/PreloadScene.ts`:
   ```ts
   this.load.spritesheet("bat", "sprites/bat.png", { frameWidth: 24, frameHeight: 24 })
   // в create():
   this.anims.create({ key: "bat-fly", frames: this.anims.generateFrameNumbers("bat", { start: 0, end: 1 }), frameRate: 8, repeat: -1 })
   ```
3. **Числа** — в `content/balance.json` (например, `"WORLD": { …, "batSpeed": 60 }`), описание и допустимый диапазон — в `content/schema.ts`, экспорт — в `src/config.ts`: `export const BAT_SPEED = BALANCE.WORLD.batSpeed`.
4. **Класс** `src/entities/Bat.ts` — по образцу `Slime.ts`: `start()` задаёт тело и скорость (вызывать **после** `group.add()` — группа сбрасывает настройки тела), `step()` — поведение в каждом кадре:
   ```ts
   start() {
     this.body.setAllowGravity(false)
     this.setVelocityX(-BAT_SPEED).play("bat-fly")
     return this
   }
   step() {
     if (this.body.blocked.left || this.body.blocked.right) this.setVelocityX(-this.body.velocity.x)
   }
   ```
   Если у врага несколько режимов (патруль → погоня → атака), заведите `StateMachine` из `src/fsm.ts` — см. «Автомат состояний».
5. **Расстановка** — в Tiled: точки с именем `bat` в слое `objects`. В `GameScene.create()` рядом со слизнями: `const bat = new Bat(this, x, y - 12); this.bats.add(bat); bat.start()`; группа, коллизии и `overlap` с игроком — как у `slimes`, в `update()` — `bat.step()`.
6. **Отклик:** при победе над врагом — `this.fx.sparks(...)`, `this.fx.hitstop()`, `this.fx.popText(...)` (см. «Ощущение от игры»).
7. **Правило** (когда враг погибает, сколько даёт очков) — функцией в `src/rules.ts` и тестом в `src/rules.test.ts`.
8. **Проверка в браузере** — шаг в `e2e/game.spec.ts`, если враг меняет основной цикл игры.

## Новый уровень

1. В Tiled: откройте `public/assets/maps/level2.tmj`, «Файл → Сохранить как…» → `level3.tmj`. Имена слоёв (`decor`, `ground`, `objects`) не меняйте.
2. Добавьте строку в `content/levels.json`: `{ "key": "level3", "file": "maps/level3.tmj", "title": "level3" }`, а название — ключом `level3` в `content/i18n/ru.json` и `en.json`. Опечатку в пути, имени слоя или ключе текста `npm run dev` покажет прямо в браузере.
3. Всё. Карта загрузится, когда игрок начнёт уровень (не при старте игры), уровень появится в выборе уровней и откроется после прохождения предыдущего. Звёзды: 1 — дошёл до флага, 2 — две трети монет, 3 — все (`starsFor()`).
4. Объекты уровня — в «Механики уровня в Tiled». Файлы, нужные только этому уровню (босс, своя музыка), — полем `"assets"`: `[{ "type": "image", "key": "boss", "url": "sprites/boss.png" }]`, они загрузятся вместе с картой. Тёмный уровень со светом — «Освещение уровня».

## Новый звук

1. Файл — в `public/assets/sounds/` (эффекты — `.wav`/`.ogg`, музыка — `.mp3`). Автора — в `CREDITS.md`.
2. `PreloadScene`: `this.load.audio("shoot", "sounds/shoot.wav")`.
3. Воспроизведение — **только** через `src/audio.ts`, тогда работают настройки громкости:
   ```ts
   playSfx(this, "shoot", 0.5)                    // эффект: высота тона чуть меняется каждый раз
   playSfx(this, "click", 0.5, { variation: 0 })  // интерфейс и мелодии — всегда одинаково
   playSfx(this, "step", 0.3, { limit: 2 })       // не больше 2 одинаковых звуков сразу
   playMusic(this, "boss", 0.3)                   // музыка: плавная смена с текущей, тот же трек не перезапускается
   stopMusic(this)                                // затихает за 0,4 с
   ```
   На паузе музыка становится тише сама (`duckMusic`).
4. **Много коротких эффектов → один файл:** см. «Аудиоспрайт».
5. **Сжатие:** `npm run audio` (нужен [ffmpeg](https://ffmpeg.org/download.html)) делает из каждого WAV файлы OGG и M4A в 5–10 раз меньше. Затем грузите оба формата — `this.load.audio("shoot", ["sounds/shoot.ogg", "sounds/shoot.m4a"])` — и уберите WAV из `public/` (оригиналы держите в `art/sounds/`).

## Новое поле в сохранении

Сохранение одно на игрока — `src/save.ts` (рекорд, копилка, прогресс уровней, достижения, ежедневная награда, настройки). Пример: купленные скины.

1. Добавьте поле в `Save` и в `DEFAULT_SAVE`: `skins: string[]`, `skins: []`.
2. В `parseSave()` — проверку: `skins: toStrings(data.skins)`. Старые сохранения без поля получат значение по умолчанию.
3. Сохраняйте через `save.update({ skins: [...save.get().skins, "gold"] })` — остальные поля сохранятся сами.
4. Тест в `src/save.test.ts`: старое сохранение без поля читается, мусор отбрасывается.

Порталы ограничивают частоту сохранений (Яндекс: 100 раз за 5 минут). Сохраняйте в конце уровня, а не в каждом кадре; для частых изменений — `save.update(patch, 1000)`.

## Новый экран (магазин, выбор уровня, настройки)

Образец — `src/scenes/PauseScene.ts`: экран поверх уровня со списком пунктов.

1. Сцена `src/scenes/LevelsScene.ts` (`class LevelsScene extends Phaser.Scene`, ключ `"levels"`), добавьте её в список `scene` в `src/main.ts`.
2. **Пункты — через `MenuList` из `src/ui.ts`:** он сам работает со стрелками, геймпадом, мышью и тапом и подсвечивает выбранный пункт (видимый фокус — требование доступности):
   ```ts
   this.controls = new Controls(this)
   this.menu = new MenuList(this, width / 2, 200, [
     { label: "Уровень 1", action: () => goTo(this, "game", { level: 1 }) },
     { label: () => volumeLabel("sound", save.get().settings.sound), action: () => { /* … */ } },
   ], this.controls)
   // update(): this.controls.update(); this.menu.update()
   ```
3. **Поверх игры:** `this.scene.launch("shop"); this.scene.pause()`; закрыть: `this.scene.stop(); this.scene.resume("game")`. Во время такого экрана — `platform.gameplayStop()`, при возврате — `platform.gameplayStart()` (требование порталов).
4. **Вместо игры:** переход с затемнением — `goTo(this, "levels")` из `src/transition.ts`, а в `create()` новой сцены — `fadeIn(this)`.

## Новый язык

1. Создайте `content/i18n/tr.json` с теми же ключами, что у `ru.json` (или новой колонкой в таблице — «Тексты в таблице»).
2. В `src/i18n.ts`: `import trTexts from "../content/i18n/tr.json"`, `const tr: Record<keyof typeof ru, string> = trTexts`, добавьте `tr` в `texts` и в `LANGUAGES`.
3. Тексты в коде — только через `t("ключ")`, без строк в сценах. Числа со словами — `fmt()` с формами: `"{n} {n:монета|монеты|монет}"`.
4. `npm run check` проверит: все ключи на месте, `{подстановки}` совпадают с русскими, форм множественного числа столько, сколько нужно языку, перевод не длиннее оригинала в 1,6 раза.

## Новая покупка

Покупки идут через `shop` из `src/shop.ts` — он знает, что куплено, и не выдаст товар дважды. Пример в шаблоне — «Убрать рекламу» (`no_ads`).

1. **Товар на портале.** Создайте его в консоли площадки (Яндекс Игры: вкладка «Покупки») с id, например `skin_gold`. Название и цена в игре придут оттуда.
2. **Постоянный товар** (скин, уровни, без рекламы): добавьте id в `PRODUCTS` в `src/shop.ts` и проверяйте `shop.has(PRODUCTS.skinGold)`.
3. **Расходуемый товар** (монеты, жизни): передайте выдачу вторым аргументом — `createShop(platform, { coins_100: () => addCoins(100) })`. Магазин выдаст товар и вызовет `consumePurchase`; оплаченный, но не выданный (закрыли вкладку) — выдаст при следующем запуске.
4. **Кнопка:** только если `shop.available` (на площадке есть покупки), подпись — `shop.product(id).price`. Покупка — `await shop.buy(id)`: `true` — оплачено и выдано, `false` — игрок закрыл окно или оплата не прошла.
5. **Проверка:** в `npm run dev` без SDK покупки бесплатные и мгновенные (хранятся в localStorage, сброс — очистить данные сайта). Тест — в `src/shop.test.ts`, шаг покупки — в `e2e/game.spec.ts`.

## Реклама за награду

```ts
const rewarded = await platform.showRewardedAd()
if (rewarded) this.registry.inc("lives", 1) // только если досмотрел
```

Показывайте только по кнопке игрока («+1 жизнь за рекламу»), никогда во время игры. Если реклама не загрузилась, `showRewardedAd()` вернёт `false` — игра продолжится без награды.

## Ассеты

- **Структура:** `public/assets/sprites`, `sounds`, `maps`, `atlas`; авторы — `CREDITS.md`.
- **Спрайты:** кадры одной анимации — в одной картинке (spritesheet). Когда спрайтов много — **атлас**: см. «Атлас спрайтов». Атлас — один запрос и одна текстура вместо десятков.
- **Анимации из Aseprite** — см. рецепт ниже: без ручной нарезки кадров.
- **Размер:** картинки — PNG, сжатие без потерь через [Squoosh](https://squoosh.app) или `oxipng`; музыка — MP3 96–128 кбит/с; эффекты — короткие WAV/OGG. Порталы ограничивают размер игры и время первой загрузки; `npm run size` (входит в `npm run check`) следит за бюджетом — лимиты в `scripts/size.mjs`.
- **Пиксель-арт:** `pixelArt: true` уже включён; размеры кадров — кратные тайлу.

## Доступность и удобство

- Всё управление дублируется: клавиатура + геймпад + тач. Код игры спрашивает **действия** (`controls.isDown("jump")`), а не клавиши — см. «Управление».
- Громкость звука и музыки — в меню (S и M) и в паузе; новые звуки — только через `src/audio.ts`.
- Настройка «Эффекты» (E в меню, пункт в паузе) выключает тряску, вспышки, стоп-кадры и фильтры. Новые резкие эффекты — только через `Fx`, он её учитывает.
- Без резких вспышек на весь экран: тряска камеры и мигание — короткие (до 0,5 с).
- Важное не передавайте только цветом: враг отличается формой, не только оттенком.
- Текст на экране — не мельче 16 px при ширине 960.
- **Настройки → Доступность** (`src/accessibility.ts`): цветовой фильтр (контраст, протанопия, дейтеранопия, тританопия — цвета сдвигаются так, чтобы их можно было различить), субтитры звуков, скорость игры 100/80/60 % (физика, таймеры и анимации замедляются вместе), помощь: +2 жизни и «Пропустить уровень» в паузе. Эти настройки не зависят от «Эффектов».
- Новый звук с субтитрами: строка в `CAPTIONS` (`src/accessibility.ts`) и текст `snd…` в `content/i18n/*.json`.

## Производительность

- Цель — **60 FPS на среднем телефоне**. FPS виден в отладочной панели (F1 в `npm run dev`). Проверка под нагрузкой: Chrome → DevTools → Performance, режим «4× slowdown».
- Пули, частицы, враги, которые появляются часто, — через пул: `group.get(x, y)` и `setActive(false).setVisible(false)` вместо `destroy()`. Частицы в `Fx` уже в пулах: один эмиттер, `explode()` сколько угодно раз.
- Не создавайте объекты в `update()` (векторы, массивы, строки текста) — переиспользуйте.
- Тексты, которые меняются каждый кадр, обновляйте только при изменении значения (как HUD через `changedata`).
- Фильтры дорогие: один фильтр на слой (`look.glowLayer()`), а не на каждый спрайт. На слабых устройствах игрок выключит «Эффекты».
- Размер сборки — `npm run size`: JS (gzip) и общий вес `dist/`.

## Ощущение от игры («сочность»)

Игра ощущается хорошей, когда на каждое действие есть отклик. Всё нужное — в `src/fx.ts`, в сцене — `this.fx`:

| Момент | Отклик |
|---|---|
| Прыжок | `fx.squash(sprite, -0.2)` — вытянуться вверх, `fx.dust(x, y)` — пыль из-под ног |
| Приземление | `fx.squash(sprite)` — сплющиться, пыль |
| Подбор предмета | `fx.sparks(x, y, цвет)`, `fx.popText(x, y, "+1")`, звук |
| Удар по врагу | `fx.hitstop()` — стоп-кадр 70 мс, `fx.sparks`, лёгкий `fx.shake()` |
| Урон игроку | `fx.flash(sprite)` — белая вспышка, `fx.shake()`, стоп-кадр подольше |

Числа (сила тряски, длина стоп-кадра, сплющивание) — в `FX` в `src/config.ts`, подбираются вживую на панели F2.

Движение героя уже «прощает» игрока (`src/movement.ts`, числа — `PLAYER` в `config.ts`):

- **coyote time** — прыжок ещё срабатывает 90 мс после схода с края;
- **буфер прыжка** — нажатие за 120 мс до приземления сработает при касании земли;
- **высота прыжка зависит от нажатия** — отпустили раньше, прыжок ниже (`jumpCut`);
- **разгон и торможение** (`accel`, `decel`), слабее в воздухе (`airControl`);
- **быстрое падение** (`fallGravity`) — прыжок не «ватный».

Камера: плавное следование, мёртвая зона и взгляд вперёд по ходу бега (`CAMERA` в `config.ts`).

## Свечение и фильтры (Phaser 4)

`src/look.ts` — «картинка» игры, только WebGL:

- **камера:** мягкая виньетка и лёгкая цветокоррекция (`LOOK` — сила и насыщенность);
- **светящийся слой:** `const glow = this.look.glowLayer()` и `glow.add(объект)` — один фильтр на все объекты слоя (монеты, искры, магия).

Свой фильтр на объект: `sprite.enableFilters(); sprite.filters!.internal.addGlow(0xff00ff, 4)`. Список фильтров — `node_modules/phaser/skills/filters-and-postfx/SKILL.md` (blur, glow, pixelate, wipe, shadow, color matrix, displacement…). Каждый новый фильтр подключайте так, чтобы настройка «Эффекты» его выключала.

## Анимации из Aseprite

[Aseprite](https://www.aseprite.org) — редактор пиксель-арта. Анимации (теги) приходят в игру без ручной нарезки кадров:

Быстрее: сохраняйте `.aseprite` в `art/aseprite/` и запустите `npm run art -- --watch` рядом с `npm run dev`: каждое сохранение в Aseprite сразу экспортируется в `public/assets/sprites/` (нужен установленный Aseprite; путь можно задать переменной `ASEPRITE`). Вручную:

1. В Aseprite: «File → Export Sprite Sheet»: Layout — Packed, Output — PNG + JSON Data, формат **Array**, Meta — **Tags** включены.
2. Файлы `hero.png` и `hero.json` — в `public/assets/sprites/`.
3. `PreloadScene`: `this.load.aseprite("hero", "sprites/hero.png", "sprites/hero.json")`, в `create()` — `this.anims.createFromAseprite("hero")`.
4. Анимации называются как теги в Aseprite: `this.player.play("run")`. Длительность кадров — тоже из Aseprite.

## Атлас спрайтов

Много отдельных картинок → одна текстура (меньше запросов, спрайты рисуются одним пакетом):

1. Сложите PNG в `art/atlas/<имя атласа>/`, например `art/atlas/items/coin.png`, `art/atlas/items/gem.png`. Подпапки дают имена кадров с `/`: `art/atlas/hero/run/1.png` → кадр `run/1`.
2. `npm run atlas` → `public/assets/atlas/items.png` + `items.json`. Запускайте после каждого изменения картинок; исходники в `art/` храните в git.
3. `PreloadScene`: `this.load.atlas("items", "atlas/items.png", "atlas/items.json")`.
4. В игре: `this.add.image(x, y, "items", "coin")`; анимация из кадров атласа — `this.anims.generateFrameNames("hero", { prefix: "run/", start: 1, end: 6 })`.

## Управление: новое действие, геймпад

Код игры не знает о клавишах — только о действиях из `src/input.ts` (`left`, `right`, `up`, `down`, `jump`, `pause`, `confirm`).

1. **Новое действие** (например, `attack`): добавьте его в тип `Action`, клавиши — в `KEYS` (`attack: ["J", "X"]`), кнопку геймпада — в `PAD_BUTTONS` (`attack: [2]` — X / □).
2. **Сенсорная кнопка:** в `HudScene.addTouchButtons()` — `button(x, y, 46, "⚔", "attack")`.
3. **В сцене:** `this.controls.justPressed("attack")` — нажали в этом кадре; `isDown` — держат; `justReleased` — отпустили. `controls.axisX` — направление от −1 до 1 (стик или клавиши).
4. Геймпад включён в `src/main.ts` (`input.gamepad: true`); раскладка стандартная (Xbox, PlayStation, большинство USB-геймпадов).

## Настройка баланса прямо в игре (F2)

В `npm run dev` работают инструменты разработчика (`src/debug/`, в сборку для игроков не попадают):

| Клавиша | Что делает |
|---|---|
| F1 | панель: FPS, сцены, состояние героя, таймеры прыжка, последние события аналитики |
| F2 | ползунки: скорость, прыжок, гравитация, камера, эффекты — меняются сразу |
| F3 | хитбоксы физики |
| F4 | бессмертие |
| F6 | пройти уровень |
| F7 / F8 | записать прохождение / воспроизвести запись (см. «Запись прохождений») |
| F9 | тепловая карта смертей; Shift+F9 — добавить смерти игроков из файла (см. «Тепловая карта смертей») |

Подобрали ощущение — нажмите «Copy values for content/balance.json» и замените файл. Новые числа добавляйте в `content/balance.json` и `content/schema.ts`, а ползунок — строкой `addBinding` в `src/debug/index.ts`.

## Автомат состояний

Когда у сущности есть режимы (герой: стоит / бежит / прыгает / падает; враг: патруль / погоня / атака), используйте `StateMachine` из `src/fsm.ts`, а не набор флагов:

```ts
this.states = new StateMachine<"patrol" | "chase" | "attack">({
  patrol: { update: () => this.walk() },
  chase: { enter: () => playSfx(this.scene, "alert"), update: () => this.follow(player) },
  attack: { enter: () => this.play("bat-bite") },
})
this.states.set("patrol")
// в step(): this.states.update(dt); переход — this.states.set("chase")
// states.elapsed — сколько мс в текущем состоянии (атака длится 400 мс и т. п.)
```

Пример — `src/entities/Player.ts`: состояние выбирает `pickPlayerState()`, а `enter` переключает анимации.

## Аналитика и ошибки

`src/telemetry.ts`: события `track(name, data)`, ошибки ловятся сами (`captureErrors()`, со стеком). Уровень сам аналитику не вызывает: он сообщает о событиях (`gameEvents`, см. «События игры»), а `src/systems.ts` превращает их в `level_start`, `level_complete`, `game_over`, `death` (причина и место), `checkpoint`. Пауза пишет `quit` и `restart`, помощь — `level_skip`.

Куда отправлять — ключи в `.env` (образец — `.env.example`), пустой ключ — сервис выключен:

| Ключ | Куда |
|---|---|
| `VITE_BACKEND_URL` | свой игровой сервер (`server/`): воронка уровней, удержание D1/D7, A/B-тесты, ошибки — «Игровой сервер» |
| `VITE_SENTRY_DSN` | Sentry или GlitchTip: ошибки со строкой в исходнике — «Ошибки в Sentry» |
| `VITE_METRICA_ID` | Яндекс Метрика: события становятся целями |

Свой приёмник: `addSink((e) => …)` в `src/main.ts`; `beaconSink(url)` шлёт пачками и переживает закрытие вкладки. Что смотреть: на каком уровне бросают игру, где умирают (тепловая карта), какие ошибки у игроков. Соблюдайте правила порталов о сборе данных: игрок анонимен (`src/player.ts` — случайный id браузера).

## Механики уровня в Tiled

Объекты ставятся в слой `objects` по **имени**, числа — свойствами объекта (Tiled: выделите объект → Свойства → «+»). В коде их читает `prop(obj, "speed", 40)` из `src/tiled.ts`; значения по умолчанию — в `src/config.ts`.

| Имя | Что это | Свойства |
|---|---|---|
| `player` (точка) | старт | — |
| `coin` | монета (звёзды считаются по монетам) | — |
| `slime` | враг-патрульный | `speed` |
| `flag` | финиш | — |
| `checkpoint` | контрольная точка: дальше возрождение здесь | — |
| `spring` | пружина: подбрасывает на `SPRING_SPEED` | — |
| `platform` (**прямоугольник**) | движущаяся платформа шириной с прямоугольник, возит игрока | `dx`, `dy` — путь в пикселях, `speed` |
| `hint` | подсказка обучения: появляется рядом с игроком | `text` — ключ из `content/i18n/*.json` |

Свойства тайлов: `collides` — твёрдый, `oneWay` — твёрдый только сверху (доски: запрыгнуть снизу), `hazard` — ранит. Новый объект: `case "имя":` в `GameScene.create()`.

## Опциональные системы

Всё, что нужно не каждой игре, включается флагами `FEATURES` в `src/config.ts`. Выключенная система просто исчезает, игра работает.

| Флаг | Что делает |
|---|---|
| `levelSelect` | экран выбора уровней со звёздами; без него «Играть» запускает уровни подряд |
| `checkpoints` | точки `checkpoint` из Tiled |
| `hints` | подсказки `hint` из Tiled |
| `parallax` | фон из слоёв, которые движутся медленнее уровня (`src/parallax.ts`) |
| `achievements` | достижения со всплывающим окном |
| `dailyReward` | награда за ежедневный вход |
| `rotatePrompt` | «поверните телефон» в вертикальном положении (для вертикальной игры — выключите) |
| `remoteConfigUrl` | адрес JSON с изменениями баланса (см. «Удалённый конфиг») |

## Достижения и ежедневная награда

- **Достижения** — список в `src/achievements.ts`: `{ id, title, check }`, где `check(save, run)` получает сохранение и итог забега (`won`, `damage`). Название — ключ в `src/i18n.ts`. Проверка вызывается в конце уровня (`unlockAchievements`), новые показываются всплывающим окном и пишутся в аналитику. Тест — в `src/meta.test.ts`.
- **Ежедневная награда** (`src/daily.ts`): день 1 — 10 монет, каждый следующий день подряд — на 10 больше, с 7-го — 70; пропуск дня начинает серию заново. Выдаётся при открытии меню. Монеты копятся в `save.wallet` — тратьте их в магазине улучшений или скинов.
- Всплывающее окно для своих событий: `toast(this.game, "Заголовок", "текст")` из `src/meta.ts`.

## Удалённый конфиг

Баланс после релиза — без новой сборки (тонкая настройка, A/B-тесты):

1. Положите JSON на любой адрес (свой сервер, GitHub Pages): `{ "PLAYER": { "jumpSpeed": 420 }, "FX": { "shake": 0.006 } }`.
2. `FEATURES.remoteConfigUrl = "https://…/balance.json"`.
3. При запуске игра загрузит файл (не дольше 3 с, ошибки не мешают игре) и поменяет только известные числа из `PLAYER`, `CAMERA`, `FX`.
4. A/B-тест в том же файле — «A/B-тесты».

## Экран настроек и переназначение клавиш

`SettingsScene` (кнопка «⚙ Настройки» или O в меню): громкость, эффекты, язык (авто → русский → английский), во весь экран, управление на телефоне (кнопки или джойстик), «Доступность →» (вторая страница), клавиши для «влево», «вправо», «прыжок», «пауза» и сброс. Новый язык из «Новый язык» появится в переключателе, если добавить его в `LANGUAGES` в `src/i18n.ts`. Новое действие для переназначения — в `REBINDABLE` в `src/input.ts` и его название в `ACTION_TITLES` в `SettingsScene`.

## Офлайн-версия (PWA)

Для своего сайта: `npm run build:web` — сборка, которая открывается без интернета после первого визита и «устанавливается» на экран телефона (манифест, иконки из `coin.png`, кэш всех файлов). GitHub Pages из шаблона уже публикует такую версию. Для порталов — только `npm run zip`: они запускают игру в своей рамке и запрещают service worker. Название и цвет — в начале `scripts/pwa.mjs`.

## Запись прохождений (F7 / F8)

В `npm run dev`: F7 на уровне — запись с начала уровня, F7 ещё раз — остановка и скачивание `replay-level1-….json`; F8 — открыть такой файл и посмотреть. Тестировщик присылает файл — вы видите ровно то, что он нажимал. Повтор близок к оригиналу; на длинных записях возможен сдвиг на несколько пикселей (разная частота кадров). Для автотеста: `replay.startPlayback(data)` в `e2e/` (пример — тест «replay» в `e2e/game.spec.ts`). Точный покадровый повтор для регрессий — «Эталонные прохождения».

## Скриншотные тесты

`e2e/visual.spec.ts` сравнивает экраны (выбор уровней, настройки) с сохранённой картинкой — так видно, что правка сломала интерфейс. Первый запуск `npm run test:e2e` на машине сохраняет картинки в `e2e/visual.spec.ts-snapshots/` — закоммитьте их. После намеренного изменения вида: `npm run test:e2e -- --update-snapshots`. Новый экран — строкой в списке в начале файла.

## Проверка производительности

`npm run test:perf` — запускает самый загруженный уровень с процессором, замедленным в 4 раза (как бюджетный телефон), и проверяет средний FPS (по умолчанию не ниже 30, своё значение — `MIN_FPS=45 npm run test:perf`). Запускайте перед релизом и после добавления частиц, фильтров, большого числа врагов.

## Жанры (шаблоны)

- `platformer` (по умолчанию) — этот проект: бег, прыжки, уровни сбоку.

## Контент в JSON

Всё, что меняет геймдизайнер, лежит в `content/`, а не в коде:

| Файл | Что в нём |
|---|---|
| `content/balance.json` | числа баланса: мир, движение героя, камера, эффекты, очки |
| `content/levels.json` | список уровней: карта, название, свои ассеты, освещение |
| `content/i18n/*.json` | тексты на каждом языке |
| `content/schema.ts` | что разрешено в этих файлах: смысл и диапазон каждого числа (справочник) |
| `content/validate.ts` | проверка всего вместе: файлы по схемам, карты уровней (слои, `player`, `flag`, подсказки), переводы |

Ошибку (`"jumpSpeeed"`, отрицательная скорость, карта без флага, пропущенный перевод) `npm run dev` показывает поверх игры, а `npm run build` и `npm run check` останавливаются с понятным сообщением. zod работает только в этих проверках и в сборку для игроков не попадает.

## Тексты в таблице

Переводчику удобнее таблица: `npm run i18n:export` → `content/i18n.csv` (колонки `key`, `ru`, `en`…), откройте в Google Таблицах или Excel. Обратно: `npm run i18n:import` — из файла, или `npm run i18n:import -- <ссылка>` — из Google Таблицы, опубликованной как CSV («Файл → Поделиться → Опубликовать в интернете → CSV»). Тогда таблица — источник текстов, а игра забирает их одной командой. Пустая ячейка не попадает в JSON — проверка покажет пропуск.

## События игры

`src/events.ts` — типизированные события: уровень сообщает, что произошло, а кому это важно — слушают.

```ts
gameEvents.emit("death", { level: 0, cause: "fall", x, y }) // в сцене
const off = gameEvents.on("death", (e) => {}) // в любой системе; off() — отписаться
```

События: `levelStart`, `death`, `checkpoint`, `levelEnd`, `sound`. Новое событие — поле в `GameEventMap` (опечатка в имени или поле станет ошибкой типов). Слушатели на всё время игры подключаются в `src/systems.ts`: сейчас там аналитика и игровой сервер. Новая система (квесты, статистика) не трогает `GameScene`.

## Повторяемая случайность

Всё случайное, что влияет на игру (выбор врага, добыча, генерация уровня), — через `rng` из `src/random.ts`, а не `Math.random()`: `rng.int(1, 6)`, `rng.pick(list)`, `rng.chance(0.2)`. `GameScene` задаёт зерно по номеру уровня, поэтому одинаковый ввод даёт одинаковую игру: записи, эталонные прохождения и проверка рекордов остаются точными. Косметика (высота звука, частицы) может брать `Math.random()`.

## Эталонные прохождения

`npm run test:golden` (входит в `npm run test:e2e`) проигрывает записи из `e2e/golden/*.replay.json` покадрово с шагом ровно 1/60 с, без отрисовки, и сравнивает итог (позиция, очки, жизни, победа) с `<имя>.<жанр>.expected.json`. Любое изменение физики, чисел движения или карты, которое меняет прохождение, видно сразу, даже если на глаз всё «как было». Тест заодно проверяет, что игра детерминирована: два прогона одной записи совпадают до сотых пикселя.

- Новая запись: F7 в `npm run dev`, файл — в `e2e/golden/`; первый прогон сохранит итог (закоммитьте его).
- Намеренно поменяли баланс: `npm run test:golden -- --update-snapshots` или удалите `.expected.json`.

## Тепловая карта смертей

F9 в `npm run dev` рисует на уровне точку на месте каждой смерти, цвет — причина (синий — шипы и вода, фиолетовый — падение, зелёный — враг, красный — остальное). Скопления показывают, где уровень нечестный. Ваши смерти копятся в браузере (сброс — кнопка на панели F2). Смерти игроков: `GET /deaths?token=…&level=1` игрового сервера → сохраните ответ в файл → Shift+F9.

## Игровой сервер

`server/` — свой сервер без зависимостей: аналитика с отчётом (`/report.html`), лидерборд с проверкой результата, облачное сохранение с кодом переноса. Запуск — `npm run server`, подключение — `VITE_BACKEND_URL` в `.env`. На площадках сервер получает только аналитику: сохранения и лидерборд остаются площадочными. Подробно — `server/README.md`.

Подозрительный рекорд: `npm run verify -- server/data/replays/1/<игрок>.json 25` проиграет его запись в настоящей игре и проверит, что она набирает 25 очков. Запись сделана на живой частоте кадров, а проверка идёт ровно по 1/60 с, поэтому разница в одну-две монеты возможна. Сильное расхождение значит, что рекорд набран не этой игрой.

## Ошибки в Sentry

1. Проект в [sentry.io](https://sentry.io) (или свой GlitchTip) → Client Keys → DSN в `.env`: `VITE_SENTRY_DSN=…`. Ошибки игроков приходят со стеком, версией сборки и браузером (не больше 20 за визит, повторы — один раз). Свою пойманную ошибку отправляет `reportError(error, "где")`.
2. Карты исходников: `npm run sentry:sourcemaps` (нужны `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT` — в окружении или в `.env.sentry.local`). Скрипт соберёт игру, отправит карты в Sentry и удалит их из `dist/`. Публикуйте этот `dist/`: в Sentry будет видна строка в `src/`.

## A/B-тесты

Игроки делятся на постоянные группы по анонимному id (`src/experiments.ts`), отчёт игрового сервера сравнивает долю побед по вариантам.

- **Только баланс, без новой сборки** — в файле удалённого конфига: `{ "experiments": { "jump": { "a": {}, "b": { "PLAYER": { "jumpSpeed": 430 } } } } }`. Половина игроков получает прыжок выше, у «a» всё как было.
- **В коде:** `if (variant("menu_layout", ["a", "b"]) === "b") { … }` — тот же игрок всегда получает тот же вариант.

Решение принимайте по достаточному числу игроков (сотни на вариант), а не по первым десяти.

## Освещение уровня

Тёмный уровень со светом вокруг героя и свечением монет задаётся строкой в `content/levels.json`, новая графика не нужна:

```json
{ "key": "level3", "file": "maps/level3.tmj", "title": "level3", "light": { "ambient": "#26213d", "radius": 140, "coins": true } }
```

`ambient` — темнота (`#000000` — пещера), `radius` — свет вокруг героя. Дальний фон затемняется, а не освещается. Для рельефа нарисуйте карту нормалей и загрузите вместе со спрайтом: `this.load.image("tree", ["tree.png", "tree_n.png"])`. Только WebGL; на Canvas уровень выглядит как обычно (`src/lighting.ts`).

## Растровый шрифт

`makeBitmapFont(this, "hud", { size: 26 })` в `PreloadScene` рисует растровый шрифт с кириллицей из любого CSS-шрифта (файлы шрифтов не нужны), дальше — `this.add.bitmapText(x, y, "hud", "Монеты: 0")`. Такой текст перерисовывается почти бесплатно: используйте его для счёта, таймера, чисел урона. Меню с переносом строк оставьте на `Text`. Счёт в HUD уже на нём (`src/bitmapFont.ts`).

## Аудиоспрайт

Много коротких эффектов → один файл (один запрос, одно декодирование на iPhone), без ffmpeg:

1. WAV-файлы — в `art/sfx/sfx/` (`jump.wav`, `coin.wav`…).
2. `npm run audio:sprite` → `public/assets/sounds/sfx.wav` + `sfx.json`.
3. `PreloadScene`: `this.load.audioSprite("sfx", "sounds/sfx.json", ["sounds/sfx.wav"])`, отдельные файлы этих звуков уберите из `public/`.
4. `playSfx(this, "jump")` найдёт звук внутри спрайта сам; громкость, высота тона, лимит копий и субтитры работают как прежде.

`npm run audio` сожмёт `sfx.wav` в OGG и M4A — укажите их в загрузке вместо WAV.

## Требования площадок

`npm run portal` — сборка и проверка того, из-за чего модерация чаще всего возвращает игру. Сборка (`scripts/portal-check.mjs`): `index.html` в корне архива, относительные пути, латиница в именах файлов, нет карт исходников и огромных файлов, внешние адреса. Браузер (`e2e/portal.spec.ts`): страница не прокручивается стрелками и пробелом, нет выделения текста и меню по долгому тапу, звука нет до первого действия игрока, в скрытой вкладке тихо и пауза, язык следует за игроком. Правила площадок меняются — сверяйтесь с их документацией.

- **ПК и Steam:** `npm run desktop:init`, `npm run desktop`, `npm run desktop:build`; достижения Steam — те же `id`, что в `src/achievements.ts`. Подробно в `DESKTOP.md`.
- **Каждый pull request** проверяет `.github/workflows/pr.yml`: все проверки, браузерные тесты и готовая сборка в артефактах.

## Версия сборки

В углу меню — `v1.2.0+3f2a9c1`: версия из `package.json` и коммит git (`__APP_VERSION__`, задаётся в `vite.config.ts`). Она же уходит в Sentry и на игровой сервер, поэтому видно, в какой сборке ошибка. Новый выпуск — поднимите `version` в `package.json`.
